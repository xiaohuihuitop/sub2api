# 项目概览

- 项目：Sub2API 的长期定制分支。
- 主交付分支：`my`；官方同步来源：`upstream/main`。
- 订阅与计费重构开发分支：`my2.0`，基线为 `my` 的 `v0.1.171` 发布提交。
- 原则：功能默认跟随官方，保留用户确认的 UI 和调度定制；同步官方后按决策记录恢复。
- 当前目标架构：`Platform` 负责账号池、模型规则、端点能力和调度；`SubscriptionPlan` 负责套餐时长/额度/倍率；`UserSubscription` 保存发放时快照并允许多实例；余额仅使用全局余额倍率。套餐与余额都是跨平台用户资产，两个倍率绝不叠乘。
- 当前调度边界：API Key 独立授权平台、套餐与余额；请求先解析唯一平台、在该平台账号池调度，再按最早到期的可用套餐扣费，套餐不可用时仅在 Key 明确允许且余额充足时回退余额。`groups`、`group_id` / `group_ids`、`account_groups` 和旧 `BillingProfile` 仅作迁移期受限兼容，预检歧义不得自动猜测或放大权限；用户专属余额倍率不参与计费，RPM override 保留。
- V2 倍率权威来源：套餐使用 `UserSubscription.rate_multiplier_snapshot`，余额使用全局 `global_balance_rate_multiplier`。旧 `Group` / `BillingProfile` / 峰时倍率只可服务旧 Key 兼容路径，绝不覆盖 V2 请求的倍率。
- V2 管理入口：`/admin/platforms` 是唯一可编辑的账号池配置页；旧 `/admin/groups` 不进入侧边栏，也不显示余额计费控制。路由和后端接口保留作历史兼容，不能删除或作为新功能入口。
- Spark shadow 账号继承父账号的 `platform_id`，不自动默认绑定、不继承旧 `group_ids`。
- 已发布历史：账号分组负责账号与路由，`BillingProfile` 负责按分组保存余额倍率、峰时和媒体价格。该模型只用于解释已发布 `my2-v0.2.0`，新开发不得沿用。
- 旧调度说明仅记录已发布 `my2-v0.2.0` 的历史实现；新开发必须以前两条“当前目标架构”和“当前调度边界”为准。
- UI 约束：暖色主题由 `tailwind.config.js`、`style.css` 和 `AppLayout.vue` 共同定义，三者必须同步保留。
- 前端：Vue 3、TypeScript、Vite、Vitest。
