# 项目概览

- 项目：Sub2API 的长期定制分支。
- 主交付分支：`my`；官方同步来源：`upstream/main`。
- 订阅与计费重构开发分支：`my2.0`，基线为 `my` 的 `v0.1.171` 发布提交。
- 原则：功能默认跟随官方，保留用户确认的 UI 和调度定制；同步官方后按决策记录恢复。
- 长期目标架构：`Platform` 负责协议适配器、统一端点能力、模型白名单、模型映射和账号集合；`SubscriptionPlan` 负责套餐时长/额度/倍率；`UserSubscription` 保存发放时快照并允许多实例；余额仅使用全局余额倍率。套餐与余额都是跨平台用户资产，两个倍率绝不叠乘。
- 调度边界：API Key 独立授权平台、套餐与余额；请求按“模型候选、Key 授权、平台统一端点、规则优先级”解析唯一平台和上游模型，在该平台账号集合中调度，再按最早到期的可用套餐扣费，套餐不可用时仅在 Key 明确允许且余额充足时回退余额。
- 账号边界：`platform_id` 是唯一可配置的平台归属。账号不配置普通模型白名单或普通模型映射；同一 Platform 的账号能力被视为一致，系统不探测或校验，管理员负责拆分不同能力账号。现有 `accounts.platform` 只作为服务端从 Platform 派生的 GatewayRuntime 适配器快照保留，客户端不可编辑，也不能成为第二个路由来源。
- V2 倍率权威来源：套餐使用 `UserSubscription.rate_multiplier_snapshot`，余额使用全局 `global_balance_rate_multiplier`。旧 `Group`、`BillingProfile` 和峰时倍率不参与 V2 请求。
- 模型定价边界：GatewayRuntime 按最终上游模型从独立定价目录计算基础费用，ProductCore 只应用套餐或余额倍率。新请求不得使用 Group 作为模型定价入口；账号倍率只用于上游成本或账号统计。
- V2 管理入口：`/admin/platforms` 是唯一平台、统一端点和模型配置页。API Key 的 `/v1/models` 只来自其已授权 Platform；账号 `credentials.model_mapping` 和旧 Group 不得参与新模型路由。新架构不回退到 `groups`、`group_id` / `group_ids`、`account_groups` 和旧平台授权。
- 路由配置重建只影响活动平台、模型规则、账号和 API Key 平台授权。用户、API Key 本体、余额、套餐、订阅实例、支付审计和历史使用记录必须保留；仍被历史数据引用的旧行只读归档，不参与新请求。
- Spark shadow 账号继承父账号的 `platform_id`，不自动默认绑定、不继承旧 `group_ids`。
- 长期架构边界：用户、API Key、平台授权、套餐、余额、倍率、用量归属与后台 UI 属于自有 `ProductCore`；Sub2API 的账号调度、OAuth 刷新、协议适配、上游失败切换和模型基础定价属于保留的 `GatewayRuntime`。当前只在同一仓库和进程内建立适配边界，不拆服务、不替换运行时。
- 已发布历史：账号分组负责账号与路由，`BillingProfile` 负责按分组保存余额倍率、峰时和媒体价格。该模型只用于解释已发布 `my2-v0.2.0`，新开发不得沿用。
- 旧调度说明仅记录已发布 `my2-v0.2.0` 的历史实现；新开发必须以前两条“当前目标架构”和“当前调度边界”为准。
- UI 约束：暖色主题由 `tailwind.config.js`、`style.css` 和 `AppLayout.vue` 共同定义，三者必须同步保留。
- 前端：Vue 3、TypeScript、Vite、Vitest。
