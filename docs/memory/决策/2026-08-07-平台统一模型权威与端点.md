# 平台统一模型权威与端点

- 状态：已确认
- 日期：2026-08-07
- 结论：Platform 是模型白名单、模型映射和统一端点能力的唯一管理员配置源；账号只选择所属 Platform，不再配置普通模型白名单或模型映射。
- 原因：账号重复配置相同模型产生多重权威来源，导致平台路由、账号调度和 `/v1/models` 可能不一致。
- 影响：新增 Platform 统一端点；平台模型规则只保存请求模型与上游模型；调度不再读取账号 `credentials.model_mapping`；API Key 的模型列表只来自已授权 Platform。
- 相关文件：`docs/superpowers/specs/2026-08-07-platform-model-authority-design.md`、`backend/ent/schema/platform.go`、`backend/ent/schema/platform_model_rule.go`、`backend/internal/service/account.go`、`backend/internal/service/gateway_scheduling.go`、`backend/internal/handler/gateway_handler.go`、`frontend/src/components/admin/platform/PlatformPoolDialog.vue`

## 长期约束

- Platform 的端点能力对该平台全部模型统一生效，不提供逐模型端点配置或覆盖。
- 平台模型同时支持白名单自映射和显式上游映射。
- 同一 Platform 下账号能力被视为一致；系统不探测、不校验，管理员负责把不同能力账号拆到不同 Platform。
- 账号创建、编辑和批量编辑不得显示或提交普通模型白名单、普通模型映射。
- 旧账号 `credentials.model_mapping` 可以保留用于回滚和审计，但不得参与 my2.0 平台路由。
- Adapter 内部协议必需的技术映射必须保留，但不能扩大 Platform 未授权模型范围。
- `/v1/models` 只按 API Key 的 Platform 授权返回精确请求模型，不再从账号或 Group 聚合。
- Sub2API 的 OAuth、协议适配、账号调度和上游失败切换继续保留。
