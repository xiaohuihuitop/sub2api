# 彻底移除旧分组配置

- 状态：已确认
- 日期：2026-08-09
- 结论：`my2.0` 不再保留 Group/Channel 旧配置、旧字段、旧 API 或运行时兼容回退；用户资产先一次性转换到 Platform、SubscriptionPlan 和余额模型，再物理删除旧 schema。
- 原因：旧分组仍参与认证、调度、计费、支付、安全策略和统计，造成双权威与不可预测回退；用户已明确允许放弃旧配置，不需要继续承担兼容成本。
- 影响：请求只依赖 Platform；API Key 只授权 Platform、套餐和余额；Account 只属于 Platform；模型价格迁到独立目录；安全策略和运维统计改用 Platform/Plan；旧 Group/Channel 管理入口和表最终删除。
- 数据保护：用户、API Key 本体、余额、套餐、订阅实例、支付和使用记录保留；有效旧资产无法转换时 migration 必须失败，不得静默删除。
- 保留能力：OAuth、协议适配、失败切换、Compact/Responses 技术配置、LiteLLM/静态价格、手工模型价格覆盖和 Channel Monitor。
- 相关文件：`docs/superpowers/plans/2026-08-09-remove-legacy-configuration.md`、`backend/internal/server/middleware/api_key_auth.go`、`backend/internal/service/model_pricing_resolver.go`、`backend/migrations/196_remove_legacy_configuration.sql`

## 已执行收口

### 账号凭据与 Spark shadow（Task 3，2026-08-09，部分完成）

- 账号凭据的最终写入边界已统一净化普通模型策略字段：`model_mapping`、`model_whitelist`、`openai_capabilities` 不会由管理员编辑、OAuth 刷新、CRS 同步、批量更新或 repository 直接写入路径重新产生。
- 普通账号模型白名单/映射和账号级端点能力不再由创建、编辑、批量编辑表单读取或提交；Compact 专属映射和适配器技术配置保持不变。
- Spark shadow 不再生成或读取 `credentials.model_mapping`，调度资格改由结构化 `quota_dimension`、父账号和 Platform 模型规则决定。
- 账号内部 `account_groups`/GroupIDs repository 投影暂不在本 Task 删除，继续作为 Task 8/9 的一次性运行时与 schema 清理范围；外部 bulk `group_ids` 已拒绝，Platform 路由不读取该投影。
- 定向 Go/Vitest/typecheck 验证均通过；本 Task 尚未提交远程发布。

### API Key 契约（Task 2，2026-08-09）

- API Key 的外部请求和响应只使用 Platform、SubscriptionPlan 和余额授权；`group_id`、`group_ids` 不再出现在服务请求、HTTP DTO、前端类型或 API Key 列表筛选器中。
- 用户端不再请求可用分组；管理员查看用户 API Key 时只展示平台授权、套餐授权和余额授权，旧的管理员分组重绑路由已移除。
- 内部旧 Group 投影暂时只作为后续 Platform 调度/计费迁移的待清理实现细节，不得重新暴露到 API、UI 或鉴权决策；Task 6/8/9 完成后删除对应实体、join、字段和测试。
- 回归证据：API Key 后端定向测试、DTO 合约测试、KeysView Vitest 和前端 typecheck 均通过。

## 计划审查结论

- 先迁移独立模型价格目录，再删除 Channel，避免丢失手工价格覆盖能力。
- 先转换有效订阅、兑换码和支付订单，再删除旧字段；无法确定转换关系时 migration 必须失败。
- 架构残留守卫在最终清理完成后创建并一次通过，不提交预期失败测试。
- 每个 Task 单独验证、精确路径暂存；当前 `backend/entgen_tmp/`、`my2.0.drawio` 和非任务改动不得误入提交。
- 计划内表名已与 migration 081、082、101、106 核对；旧 migration 不修改，只新增 migration 196。

## 取代的旧结论

- 取代“旧 Group 字段保留一个兼容周期”的策略。
- 取代“账号普通 model_mapping 作为回滚数据长期保留”的策略。
- 取代 Platform `legacy_group_id` 和 PricingGroupID 的只读桥接策略。
- 旧 migration 和历史设计文档只用于解释已发布版本，不再作为新实现依据。
