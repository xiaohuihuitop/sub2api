# OpenAI 端点三态与多账号套餐能力

- 状态：已确认
- 日期：2026-07-12
- 结论：Responses 模式决定对外开放的入站端点；套餐能力取账号能力并集，请求调度时再过滤兼容账号。
- 原因：`v0.1.156` 将上游协议探测结果误当成入站端点能力，导致多分组 API Key 的 `/chat/completions` 在鉴权阶段被错误过滤。
- 影响：OpenAI 账号能力、API Key 多分组计费选择、HTTP/WebSocket Responses 账号调度和鉴权缓存。
- 相关文件：`backend/internal/service/account.go`、`backend/internal/repository/api_key_repo.go`、`backend/internal/handler/openai_gateway_handler.go`、`backend/internal/service/api_key_auth_cache_impl.go`

## 固定语义

| Responses 模式 | 入站 Chat Completions | 入站 Responses | 实际上游协议 |
|----------------|-----------------------|----------------|--------------|
| `auto` | 开放 | 开放 | 跟随自动探测，可在 Responses 与 Chat 间转换 |
| `force_responses` | 关闭 | 开放 | Responses |
| `force_chat_completions` | 开放 | 关闭 | Chat Completions |

- `credentials.openai_capabilities` 中的 `chat_completions` 是文本转发总开关；关闭后两个文本入站端点都不可用。
- Embeddings 能力独立，不受 Responses 三态影响。
- OAuth 账号默认开放两个文本入站端点。
- `openai_responses_supported` 只供 `auto` 模式选择上游协议，不得用于关闭任一入站端点。

## 多账号套餐规则

- 套餐能力是套餐内账号能力的并集，不是交集。
- Chat 请求只在支持 Chat 入站端点的账号中调度。
- Responses HTTP 和 WebSocket 请求只在支持 Responses 入站端点的账号中调度。
- 两个账号都支持两个端点时，两个请求都可按正常负载策略选择任一账号。
- 一个账号支持两个端点、另一个只支持 Chat 时，Chat 可选两个账号，Responses 只能选第一个账号。
- 分组选择、实际账号选择和最终计费分组必须保持一致。

## 同步复查

每次合并官方更新后至少复查：

1. `Account.SupportsOpenAIEndpointCapability` 是否仍保持三态语义。
2. 套餐能力汇总是否仍逐账号取并集。
3. HTTP Responses 与 Responses WebSocket 是否传入 `OpenAIEndpointCapabilityResponses`。
4. Chat Completions 与 Messages 是否继续传入 `OpenAIEndpointCapabilityChatCompletions`。
5. 上游协议仍由 `openai_compat.ShouldUseResponsesAPI` 决定。
6. 修改能力快照结构或语义时是否升级 `apiKeyAuthSnapshotVersion`。

## 验证方式

- 账号三态与显式文本能力测试：`TestAccountSupportsOpenAIEndpointCapability`
- 套餐能力汇总测试：`TestOpenAIAccountBillingEndpointCapabilities`
- 同套餐强制模式账号选择测试：`TestOpenAIGatewayService_SelectAccountWithScheduler_ForcedModesUseMatchingInboundEndpoint`
- 计费分组端点过滤测试：`TestResolveBillingGroup*`
