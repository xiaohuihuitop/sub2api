# 平台模型权威实施结果

- 日期：2026-08-07
- 分支：`my2.0`
- 状态：代码与回归已完成，等待发布授权

## 实施内容

- 平台统一保存端点能力、模型白名单和模型映射；同一平台的全部模型共享端点策略。
- 平台账号池负责账号调度。账号只维护 `platform_id`、凭证和调度/技术属性，不再提供普通模型白名单、普通模型映射或 Chat/Responses 端点编辑。
- 平台路由在调度、转发、WebSocket、计数 Token、媒体和兼容协议入口统一使用平台模型规则；旧账号模型策略不再决定平台请求是否可用。
- API Key 使用平台授权返回 `/v1/models` 精确目录；未授权平台、空授权和无模型不会退回旧 Group 或全局模型列表。
- 旧账号 `model_mapping`、`model_whitelist`、`openai_capabilities` 保留为回滚数据。账号更新缺省这些字段时，服务端合并逻辑保留原值；平台运行时忽略它们。
- Compact 专属映射、图片/媒体能力、适配器技术映射、OAuth 刷新、账号调度、限流和上游失败切换继续由 GatewayRuntime 负责。

## 数据与代码边界

- 新迁移：`backend/migrations/195_platform_endpoint_capabilities.sql`
- 活动 Ent 字段：`Platform.EndpointCapabilities`
- 规则接口不再把端点能力作为管理员输入；运行时规则从所属 Platform 派生端点。
- 平台模型策略集中在 `backend/internal/service/platform_model_policy.go`。
- 平台模型目录集中在 `backend/internal/service/platform_models_list.go`。
- 前端平台编辑器使用 `frontend/src/components/admin/platform/platformModelRules.ts` 和 `PlatformPoolDialog.vue`。

## 后续规则

- 后续同步官方版本时，先保留 Platform 统一模型权威边界，再解决官方冲突；不要把普通模型配置重新加回账号表单或账号运行时筛选。
- 如需新增模型，只修改对应 Platform 的模型规则；如需调整 Chat/Responses 能力，只修改 Platform 端点能力。
- 发布前仍需单独完成提交、Tag、推送、GitHub Docker 构建和腾讯云验收；本次实施不代表已部署。

## 发布前审查修复

- 审查发现 Antigravity 的 Claude、Gemini 和兼容协议实际转发仍调用账号级 `getMappedModel`，导致 Platform 的上游模型映射可能不生效。
- 已新增 `resolveAntigravityRequestModel`：Platform 路由优先使用 `ResolvedUpstreamModel`，无映射时使用请求模型；非 Platform 旧路径继续使用账号映射。
- 审查发现 Platform 路由把 Live、Alpha Search 和 Responses 的账号技术限制全部短路。
- 已新增 `Account.SupportsOpenAIEndpointTechnicalCapability`，Platform 路由只绕过管理员配置的普通端点白名单，仍保留 OAuth/API Key 类型、Live、Responses 探测、Alpha Search、Embeddings 和 Grok 媒体资格检查。
- 新增并通过 Antigravity 平台映射优先级、Live/Alpha/Responses 技术约束回归测试；服务层全量回归再次通过。
