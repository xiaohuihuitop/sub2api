# 平台池统一入口与账号适配器派生设计

- 状态：待用户复核
- 日期：2026-08-06
- 目标分支：`my2.0`

## 目标

将“平台”和“平台账号池”统一为一个用户可见概念。管理员创建或编辑账号时只选择所属平台池；账号使用的协议适配器由平台池配置派生，避免同一个账号表单出现两个容易混淆的平台选择项。

## 当前问题

当前 `Platform` 实体已经同时承担账号池、模型规则、端点能力和账号关联，但账号表单还保留一个 `platform` 适配器切换项，再显示一个 `platform_id` 平台池选择项。这样会让用户误以为需要先选协议平台，再选另一个账号池。

## 设计结论

### 领域模型

- `platforms` 表中的一条记录就是一个业务平台账号池，例如 `openai`、`glm` 或 `codex`。
- 平台池负责名称、编码、启停状态、模型匹配规则、上游模型映射、端点能力和账号集合。
- `accounts.platform_id` 是账号所属平台池的唯一新入口，一个账号只能属于一个平台池。
- `platforms.account_platform` 与旧 `accounts.platform` 保留为内部运行适配器，用于选择认证、OAuth 刷新、协议转换和请求处理逻辑，不再作为第二个业务平台让用户手动选择。
- `groups`、`group_id`、`account_groups` 继续保留兼容读取，不参与新的平台账号创建和 V2 调度。

### 账号表单

- 创建和编辑账号只显示“所属平台”选择，选项来自启用的平台池。
- 选中平台池后，表单内部自动使用该池的 `account_platform`，现有 OAuth、API Key、代理和协议相关表单继续按适配器渲染。
- 适配器以只读辅助信息显示或完全隐藏，不再提供第二个可编辑平台切换控件。
- 新建账号必须提交有效的 `platform_id`；旧账号没有 `platform_id` 时保留兼容编辑路径，但编辑时应提示管理员重新归属平台池。
- 后端以平台池的 `account_platform` 为权威值。客户端同时提交的旧 `platform` 只用于兼容校验，不能覆盖平台池配置；不一致时返回明确的配置错误。

### 请求调度

- API Key 继续授权一个或多个平台池。
- 请求先根据模型规则和端点能力解析唯一目标平台池，再在该池的账号集合中调度。
- 同一模型命中多个平台池时返回歧义错误，不根据账号字段或旧分组自动猜测。
- 套餐、余额、倍率和用量归属逻辑不变；它们仍是跨平台用户资产。

### GLM 兼容方式

- 若 GLM 使用 OpenAI 兼容协议，GLM 平台池的 `account_platform` 使用 `openai`，通过模型规则和上游模型映射区分 GLM，不新增协议适配器。
- 只有 GLM 原生协议与现有适配器不兼容时，才另行增加 GLM 适配器；本次设计不包含该扩展。

## 错误处理

- 没有启用的平台池时，账号创建按钮保持可见但提交时阻止并提示先创建平台池。
- 已停用的平台池不能新建账号；编辑旧账号时可以显示当前停用池，但不能将新账号加入其中。
- 平台池与适配器不匹配时，后端拒绝保存并返回可读错误，不静默改写凭证类型。

## 验证范围

- 前端回归测试：选择平台池后适配器表单随之变化；切换平台池不会保留不兼容的认证状态；提交同时带有正确的 `platform_id` 和派生适配器。
- 后端单元测试：创建和更新时平台池适配器的权威性、缺少平台池和适配器不一致的错误路径。
- 调度回归测试：同一模型在唯一平台池中选择账号；多平台命中时返回歧义；平台池内多账号仍支持失败切换。
- 现有 OAuth、协议适配、计费和旧数据兼容测试必须继续通过。

## 不在本次范围

- 不删除 `accounts.platform`、`platforms.account_platform` 或旧分组字段。
- 不重写 Sub2API 的 OAuth 刷新、协议适配、账号调度和上游失败切换实现。
- 不修改套餐扣费、余额倍率、模型基础价格或使用记录字段。
- 不新增 GLM 原生协议适配器。
